# Proposal: Metadata Dictionary and Structured Forensic Properties

## Why
Currently, `get_document_metadata` filters out more than 90% of the structured forensic metadata generated by IPED decoders because of a rigid 20-field whitelist (`ALLOWED_METADATA_KEYS` in `IpedCoreService.java`). This deprives the LLM of crucial details such as message direction (incoming/outgoing), GPS coordinates, web search queries, camera EXIF, and Cellebrite UFED attributes, forcing examiners to rely on noisy free-text searches.

Now that the core MCP server and synchronization baseline (v1.0.1) are established, exposing the full vocabulary of IPED parsers gives the LLM the forensic precision required to conduct surgical queries across communications, system logs, and digital media.

## What Changes
- **Unblock Forensic Metadata**: Replace the restrictive `ALLOWED_METADATA_KEYS` whitelist with a domain-aware semantic sanitizer that retains forensic fields (`Communication:*`, `Conversation:*`, `common:geo:*`, `image:*`, `video:*`, `audio:*`, `ufed:*`, `p2p:*`, `hashDb:*`) while suppressing low-level internal Lucene index buffers.
- **New Tool `get_property_dictionary`**: Introduce an MCP tool allowing the LLM to inspect indexed field names, data types, descriptions, and escaping conventions across forensic domains (`chats`, `browsers`, `emails`, `media`, `system`, `gps`, `ufed`, `ai`).
- **New Tool `list_available_properties`**: Introduce an MCP tool that returns the distinct property keys actually populated in the active case for a specific category (e.g. `chat messages`, `browsers/history`).
- **Structured Metadata Output**: Group properties in `get_document_metadata` into semantic sections (`basic`, `communication`, `geo`, `forensic`, `extra`) to optimize LLM comprehension and token usage.

## Capabilities

### New Capabilities
- `metadata-dictionary`: Provides domain-specific field catalogs and schema inspection tools (`get_property_dictionary`, `list_available_properties`) to guide LLM query construction.

### Modified Capabilities
- `forensic-query-tools`: Updates `get_document_metadata` to return domain-structured metadata and preserve parser-extracted forensic properties without loss.

## Impact
- **Service Layer**: `IpedCoreService.java` updated with semantic property categorization, domain dictionary mapping, and category-level property aggregation.
- **MCP Tools**: New `PropertyDictionaryTool.java` registered with `@Tool` annotations; `DocumentMetadataTool.java` updated with enhanced prompt engineering and response schema.
- **Backward Compatibility**: Fully backward-compatible; existing queries and tools continue to function while returning richer metadata.
