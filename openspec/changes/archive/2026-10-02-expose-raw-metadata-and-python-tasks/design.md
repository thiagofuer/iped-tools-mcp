# Design: Expose Raw Metadata and Python Task Artifacts

## Context
See `proposal.md` for motivation. Currently, `IpedCoreService.getDocumentMetadata` calls `sanitizeProperties` indiscriminately, which enforces a restrictive key whitelist, truncates strings to 500 characters, truncates lists to 10 elements, and partitions fields into fixed semantic blocks. In addition, fields generated by IPED's Python and JavaScript tasks (`SearchHardwareWallets.py`, `CSAMDetectorTask.py`, `NSFWNudityDetectTask.py`, `AgeEstimationTask.py`) are ignored because their prefixes are absent from `WHITELIST_PREFIXES`.

## Goals / Non-Goals

**Goals:**
- Provide optional full-fidelity metadata retrieval (`raw: true`) without string/list truncation or arbitrary partitioning.
- Support surgical key filtering (`keys: List<String>`) with glob/wildcard support (e.g. `["Hardware-Wallet-*", "ai:*"]`).
- Whitelist and properly classify metadata fields produced by IPED Python tasks in both standard and raw modes.
- Document Python task fields in `PropertyDictionaryTool` under `ai` and `crypto` domains.
- Expand `AiDetectionTool` filters to recognize neural CSAM detection, hardware crypto wallets, age estimation, and Python NSFW scores.

**Non-Goals:**
- Modifying IPED's underlying Python scripts or execution runtime (only querying and exposing results already indexed by IPED).
- Removing the `get_document_text` pagination tool (large full-text bodies continue to be served via text chunking).
- Modifying SQLite database files or bookmarks on disk during metadata reads (read-only constraint).

## Decisions

### 1. Dual-Mode Metadata Pipeline in `IpedCoreService`
- **Method Signature**: Update `getDocumentMetadata` and `getDocumentMetadataBatch`:
  ```java
  public Map<String, Object> getDocumentMetadata(int itemId, boolean raw, List<String> keys)
  ```
- **Wildcard Key Matching**: A helper method matches document fields against the requested `keys` patterns using case-insensitive glob matching (converting `*` to `.*`).
- **Processing Flow**:
  1. Read fields from Lucene `Document`.
  2. If `keys != null && !keys.isEmpty()`, filter fields matching any key pattern.
  3. If `raw == true`: Exclude only strict engine internal noise (blacklisted Lucene internal buffers like `_content`, `treenode`, `content`), and return the complete un-truncated map directly under `"properties"`.
  4. If `raw == false`: Route through `sanitizeProperties` to generate partitioned semantic blocks with token-safety truncation.

*Alternatives considered*:
- *Separate new tool `get_raw_metadata`*: Rejected to avoid tool bloat in the MCP catalog when an optional parameter on the existing tool is standard and backwards-compatible.

### 2. Whitelist Expansion and Semantic Mapping for Python Task Fields
- Add to `WHITELIST_PREFIXES`:
  - `"ai:"` (for `CSAMDetectorTask`)
  - `"nsfw"` (for `NSFWNudityDetectTask`)
  - `"hardware-wallet-"` (for `SearchHardwareWallets`)
  - `"faceage:"` (for `AgeEstimationTask`)
- **Block Assignment in `sanitizeProperties`**:
  - `ai:`, `nsfw`: Mapped to `forensicBlock`.
  - `hardware-wallet-`: Mapped to `extraBlock`.
  - `faceage:`: Mapped to `extraBlock`.

### 3. Expansion of Forensic Domains in `PropertyDictionaryTool`
- Add `"crypto"` to `FORENSIC_DOMAINS` cataloging `Hardware-Wallet-Found`, `Hardware-Wallet-VendorID`, `Hardware-Wallet-ProductID`, `Hardware-Wallet-VendorName`, `Hardware-Wallet-DeviceName`.
- Update `"ai"` domain with neural CSAM detection fields, age estimation fields, and NSFW scores.

### 4. Enriched Detections in `AiDetectionTool`
- **`csam`**: Combine hash database hits and neural detection:
  `childPornHashHits:[1 TO *] OR hashDb\:status:alert OR ai\:csamDetector\:csam:[0.6 TO 1.0] OR ai\:csamDetector\:label:csam`
- **`crypto_wallets`**: New filter querying `Hardware-Wallet-Found:true OR bookmark:"Possible Hardware Wallets"`.
- **`age_estimation`**: New filter querying `faceAge\:count\:Child:[1 TO *] OR faceAge\:labels:Child`.
- **`nsfw`**: Support `nsfw_nudity_score:[50 TO 100]` in addition to existing `nudityScore`.

## Risks / Trade-offs

- **[Risk] High token consumption when `raw: true` is called without key filters on large items.**  
  → *Mitigation*: Tool description explicitly instructs the model to use key filtering (e.g. `keys: ["Hardware-Wallet-*"]`) when investigating specific artifacts, and defaults `raw` to `false`.

- **[Risk] Missing fields if IPED case did not run specific Python tasks during processing.**  
  → *Mitigation*: All queries gracefully handle missing fields (returning count 0 or omitting unpopulated keys) without throwing exceptions.
