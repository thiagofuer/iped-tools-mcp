# Spec Delta

## MODIFIED Requirements

### Requirement: Metadata Extraction
The server SHALL expose `get_document_metadata` to retrieve forensic metadata for one or more item IDs, reporting structured, categorized properties (`basic`, `communication`, `geo`, `forensic`, `extra`) by default and supporting full-fidelity un-truncated extraction (`raw: true`) as well as surgical field filtering (`keys`).

#### Scenario: LLM retrieves properties for candidate item IDs
- **WHEN** the LLM requests metadata for a list of document IDs with default parameters
- **THEN** the server returns categorized properties for each item, including message directions, participants, timestamps, coordinates, and hashes, while suppressing internal Lucene engine buffers and applying token-safety limits (500-character string truncation and 10-item list limits).

#### Scenario: LLM inspects chat message or photo with GPS
- **WHEN** the requested document is a WhatsApp message or a JPEG with EXIF coordinates
- **THEN** the metadata response includes `Communication:*` properties or `common:geo:locations` without being stripped by filtering.

#### Scenario: LLM requests complete raw metadata without truncation
- **WHEN** the LLM calls `get_document_metadata` with `raw: true`
- **THEN** the server returns all indexed Lucene properties for the item without semantic block partitioning and without 500-character or 10-item truncation limits, excluding only internal Lucene engine noise and raw text buffers.

#### Scenario: LLM requests surgical metadata filtered by keys or patterns
- **WHEN** the LLM calls `get_document_metadata` with a `keys` filter list (e.g. `["Hardware-Wallet-*", "ai:*", "Communication:From"]`)
- **THEN** the server returns only the properties matching the specified exact names or wildcard patterns, applying un-truncated values if `raw: true` or standard token limits if `raw: false`.

#### Scenario: LLM inspects properties generated by IPED Python tasks
- **WHEN** the requested item contains metadata produced by IPED Python or JavaScript tasks (e.g. `Hardware-Wallet-VendorName`, `ai:csamDetector:csam`, `nsfw_nudity_score`, `faceAge:labels`)
- **THEN** the server preserves and includes these attributes in the response rather than discarding them through sanitization whitelists.
