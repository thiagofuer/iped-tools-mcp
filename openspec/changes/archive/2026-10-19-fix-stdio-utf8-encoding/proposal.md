# Proposal

## Why

On Windows, Java 21 initializes `System.out`, `System.err`, and `System.in` using the native Windows codepage (`stdout.encoding=Cp1252`, `stderr.encoding=Cp1252`, `stdin.encoding=Cp1252`) despite `file.encoding` defaulting to `UTF-8` (JEP 400). Because `quarkus-mcp-server-stdio` captures `System.out` at startup (`StdioMcpServerRecorder`) and writes JSON-RPC responses via `PrintStream.println(message.encode())`, forensic evidence metadata containing Portuguese diacritics (e.g., `Relatório.ufdr`, `Perícia`), Unicode symbols, or WhatsApp emojis is emitted as `Cp1252` bytes or `'?'` and corrupted into Unicode Replacement Characters (`\uFFFD` ``) by UTF-8 MCP clients.

## What Changes

- Rebind `System.out` and `System.err` to `StandardCharsets.UTF_8` (`new PrintStream(new FileOutputStream(FileDescriptor.out), true, StandardCharsets.UTF_8)`) and enforce UTF-8 system properties at the very start of `McpApplication.main()` before `Quarkus.run(args)` captures `System.out`.
- Inject explicit JVM UTF-8 properties (`-Dfile.encoding=UTF-8`, `-Dstdout.encoding=UTF-8`, `-Dstderr.encoding=UTF-8`, `-Dstdin.encoding=UTF-8`) into `scripts/package_app.ps1` so the native `jpackage` launcher (`app/IPED-Tools-MCP.cfg`) initializes all standard I/O streams in UTF-8 from JVM bootstrap.
- Include explicit UTF-8 JVM properties in the fallback `.jar` client configuration snippet generated by `MainWindow.java`.
- Configure `StandardOutputEncoding` and `StandardInputEncoding` as `[System.Text.Encoding]::UTF8` in `scripts/test_stdio_mcp.ps1` and `scripts/test_native_exe.ps1`, adding automated assertions that verify diacritics (such as `Perícia` / `Relatório`) are transmitted without `\uFFFD` replacement characters.

## Capabilities

### New Capabilities

### Modified Capabilities
- `mcp-server-core`: Require `STDIO JSON-RPC Transport` to enforce `UTF-8` encoding across `stdin`, `stdout`, and `stderr` prior to Quarkus STDIO recorder initialization, preserving diacritics and Unicode characters in forensic evidence names, texts, and queries.
- `native-packaging`: Require `JVM Reflection and Security Configuration` in `app/IPED-Tools-MCP.cfg` to include `-Dfile.encoding=UTF-8`, `-Dstdout.encoding=UTF-8`, `-Dstderr.encoding=UTF-8`, and `-Dstdin.encoding=UTF-8`.
- `gui-configurator`: Require `1-Time LM Studio Configuration Assistance` (and JAR fallback JSON snippets) to include UTF-8 stream encoding JVM options when generating direct `java -jar` configurations.

## Impact

- `src/main/java/br/com/ipedtools/mcp/McpApplication.java` (early `System.out` / `System.err` UTF-8 rebinding and system properties)
- `src/main/java/br/com/ipedtools/mcp/gui/MainWindow.java` (JAR fallback configuration snippet)
- `scripts/package_app.ps1` (`$jvmOptions` for `jpackage`)
- `scripts/test_stdio_mcp.ps1` and `scripts/test_native_exe.ps1` (UTF-8 pipe encoding and non-ASCII character integrity checks)
- `src/test/java/br/com/ipedtools/mcp/tools/McpToolsTest.java` (unit test verifying UTF-8 `System.out` stream configuration)
